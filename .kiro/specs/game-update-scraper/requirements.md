# Requirements Document

## Introduction

KIKI는 승리의 여신 니케, 마비노기 모바일, 명조 게임의 최신 업데이트 정보를 30분마다 스크래핑하고, 내용을 분석 및 요약하여 이메일로 발송하는 서비스입니다. 현재 시장에 게임 업데이트 정보를 통합적으로 제공하는 서비스가 부재한 상황에서, MVP를 통해 시장 반응을 빠르게 확인하고자 합니다. 7일 내에 구현 가능한 최소 기능으로 구성됩니다.

## Requirements

### Requirement 1

**User Story:** 서비스 관리자로서, 승리의 여신 니케, 마비노기 모바일, 명조 게임의 공지사항을 실시간에 가깝게 자동으로 수집하고 싶습니다. 그래야 수동으로 각 사이트를 확인하지 않아도 됩니다.

#### Acceptance Criteria

1. WHEN 30분마다 스케줄링된 시간이 되면 THEN 시스템은 스크래핑 작업을 실행해야 합니다
2. WHEN 스크래핑 작업이 실행되면 THEN 시스템은 승리의 여신 니케, 마비노기 모바일, 명조 3개 게임의 공지사항 페이지를 스크래핑해야 합니다
3. WHEN 공지사항을 스크래핑하면 THEN 시스템은 제목, URL, 게시일자, 내용 요약을 추출해야 합니다
4. WHEN 스크래핑이 완료되면 THEN 시스템은 새로운 공지사항만 데이터베이스에 저장해야 합니다
5. IF 스크래핑 중 오류가 발생하면 THEN 시스템은 오류 로그를 기록하고 다음 게임사 스크래핑을 계속해야 합니다

### Requirement 2

**User Story:** 게임 업데이트에 관심있는 사용자로서, 이메일 주소만으로 간편하게 구독하고 싶습니다. 그래야 복잡한 회원가입 없이도 서비스를 이용할 수 있습니다.

#### Acceptance Criteria

1. WHEN 사용자가 랜딩 페이지에 접속하면 THEN 시스템은 이메일 입력 폼과 구독 버튼을 표시해야 합니다
2. WHEN 사용자가 유효한 이메일 주소를 입력하고 구독 버튼을 클릭하면 THEN 시스템은 구독 정보를 데이터베이스에 저장해야 합니다
3. WHEN 구독이 성공하면 THEN 시스템은 구독 성공 페이지로 리다이렉트해야 합니다
4. IF 이미 구독된 이메일 주소라면 THEN 시스템은 "이미 구독된 이메일입니다" 메시지를 표시해야 합니다
5. IF 유효하지 않은 이메일 형식이면 THEN 시스템은 "올바른 이메일 주소를 입력해주세요" 메시지를 표시해야 합니다

### Requirement 3

**User Story:** 구독자로서, 매일 게임 업데이트 요약 정보를 이메일로 받고 싶습니다. 그래야 놓치는 중요한 업데이트 없이 정보를 확인할 수 있습니다.

#### Acceptance Criteria

1. WHEN 스크래핑 작업이 완료되고 새로운 공지사항이 있으면 THEN 시스템은 모든 구독자에게 이메일을 발송해야 합니다
2. WHEN 이메일을 발송하면 THEN 시스템은 게임사별로 그룹화된 공지사항 목록을 포함해야 합니다
3. WHEN 이메일 내용을 구성하면 THEN 시스템은 각 공지사항의 제목, 요약, 원문 링크를 포함해야 합니다
4. WHEN 이메일을 발송하면 THEN 시스템은 HTML 형식의 깔끔한 템플릿을 사용해야 합니다
5. IF 해당 날짜에 새로운 공지사항이 없으면 THEN 시스템은 이메일을 발송하지 않아야 합니다

### Requirement 4

**User Story:** 구독자로서, 구독을 취소하고 싶을 때 간편하게 할 수 있어야 합니다. 그래야 원하지 않는 이메일을 계속 받지 않아도 됩니다.

#### Acceptance Criteria

1. WHEN 이메일 하단에 구독 취소 링크가 있으면 THEN 사용자는 클릭하여 구독을 취소할 수 있어야 합니다
2. WHEN 구독 취소 링크를 클릭하면 THEN 시스템은 해당 이메일 주소의 구독을 비활성화해야 합니다
3. WHEN 구독 취소가 완료되면 THEN 시스템은 구독 취소 확인 페이지를 표시해야 합니다
4. WHEN 구독이 취소된 이메일 주소는 THEN 시스템은 더 이상 이메일을 발송하지 않아야 합니다

### Requirement 5

**User Story:** 사용자로서, 과거에 발송된 공지사항 목록을 웹에서 확인하고 싶습니다. 그래야 놓친 정보를 다시 찾아볼 수 있습니다.

#### Acceptance Criteria

1. WHEN 사용자가 과거 공지사항 페이지에 접속하면 THEN 시스템은 최근 30일간의 공지사항 목록을 표시해야 합니다
2. WHEN 공지사항 목록을 표시하면 THEN 시스템은 날짜별, 게임사별로 그룹화하여 보여줘야 합니다
3. WHEN 각 공지사항을 표시하면 THEN 시스템은 제목, 게임사, 게시일자, 요약을 포함해야 합니다
4. WHEN 공지사항 제목을 클릭하면 THEN 시스템은 원본 게임사 페이지로 새 창에서 이동해야 합니다
5. WHEN 페이지를 로드하면 THEN 시스템은 Soft UI 디자인을 적용하여 부드러운 느낌을 제공해야 합니다

### Requirement 6

**User Story:** 서비스 관리자로서, 시스템이 안정적으로 운영되어야 합니다. 그래야 사용자에게 지속적인 서비스를 제공할 수 있습니다.

#### Acceptance Criteria

1. WHEN 데이터베이스 연결이 실패하면 THEN 시스템은 재시도 로직을 실행해야 합니다
2. WHEN 이메일 발송이 실패하면 THEN 시스템은 실패한 이메일 목록을 로그에 기록해야 합니다
3. WHEN 스크래핑 대상 사이트가 변경되면 THEN 시스템은 유연하게 대응할 수 있는 구조여야 합니다
4. WHEN 시스템 오류가 발생하면 THEN 시스템은 상세한 오류 로그를 기록해야 합니다
5. IF 메모리 사용량이 임계치를 초과하면 THEN 시스템은 가비지 컬렉션을 수행해야 합니다
